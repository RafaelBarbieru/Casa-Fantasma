# Casa Fantasma — notes for Claude

Point-and-click horror game built from pre-rendered art. **No engine, no runtime dependencies, no bundler.**
Vanilla ES modules plus raw WebGL1. Targets: itch.io (zip upload), self-hosting, and phone/tablet/desktop browsers.
Roles: the user owns the art and design and does not read the code, so optimise the code for my own maintenance, not for their reading.
The user-facing docs are in README.md; keep them in sync when workflows change.

## Hard constraints
- No game engine or framework. Small, self-written modules are fine. Prefer zero npm deps; if a build step is ever needed, use esbuild only.
- Every path must be **relative** (no leading `/`). itch.io serves the game from a CDN subpath.
- Paths are **case-sensitive** on itch.io and Linux hosts. `npm run build` checks the `src` paths in `data/*.json` for exact case.
- ES modules need HTTP, not `file://`. Use `npm run dev`.
- Mobile first: render on demand, cap DPR (`CONFIG.maxDpr`) and backbuffer width (`maxViewportW`). Handle touch through Pointer Events.
- GLSL ES 1.00 / WebGL1 only, so it runs everywhere. Item textures are padded to POT so mipmaps work.

## Art pipeline (as delivered)
The user said "GLB", but they actually deliver **pre-rendered WebP**:
- Rooms: `assets/rooms/*.webp`, opaque, 1920×1080. This equals the scene coordinate space (`CONFIG.sceneW/H`).
- Items: `assets/items/*.webp`, with alpha, cropped. On screen size = native px × `item.scale` × `slot.scale`.
Sources live in `art-src/` (png/jpg -> lossy q90 WebP, webp copied as-is) and `tools/images.mjs` writes `assets/**/<name>.webp`. Data files reference the generated `assets/...webp` paths.
Do not add a 3D runtime unless the user explicitly asks for one.

## Audio pipeline
- Masters are `audio-src/**/*.wav`, tracked with LFS and never shipped.
- `tools/audio.mjs` (runs from the predev, predev:lan and prebuild hooks) uses ffmpeg to write `assets/audio/**/<name>.ogg` (Opus) and `<name>.m4a` (AAC).
  - It is incremental (by mtime), deletes orphaned outputs, and preserves the channel count (mono or stereo, >2 downmixed).
  - Bitrates are in `RATES`: Opus 64k mono / 112k stereo, AAC 96k / 160k. Sample rate is 48 kHz.
- `src/audio.js` `audioUrl(name)` returns a URL for ONE format, chosen with `canPlayType` (Opus preferred).
  - SFX: `CONFIG.sfx` maps role -> name; `loadSfx` decodes them into AudioBuffers at boot, `unlockAudio()` runs on the start overlay gesture, `playSfx(name)` plays. `game.onSfx(role)` -> `playSfx(CONFIG.sfx[role])` (roles: itemClick, doorOpen, doorLocked, doorUnlock, keyFound, back; all keypress_01 for now).
  - Long ambience/music should stream through an `<audio>` element plus MediaElementSource, because decoded PCM costs ~23 MB per stereo minute (a mobile memory risk).
  - Level ambience: `generateWorld` picks `world.ambience` from `CONFIG.ambience.loops` (seeded, after the rooms, so layouts don't shift). `src/ambience.js` `setLevelAmbience(world)` -> `audio.playLoop()`: ONE reused `<audio loop>` element -> MediaElementSource -> GainNode (fades; reuse keeps iOS unlocked). Requests before the gesture are queued and start in `unlockAudio()`.
  - Random one-shots: `CONFIG.ambience.random` (pool, gapS, firstDelayS, chance, volume), decoded with the SFX at boot, setTimeout chain, Math.random (not seeded), no immediate repeats, skipped while hidden. The tab going hidden suspends the context and pauses the bed.
  - Decode during loading or room transitions, not mid-interaction.

## Layout
```

src/main.js         boot, on-demand rAF loop (wake()), resize, input wiring, world regeneration
src/config.js       ALL tunables (flashlight, shadow, glow, transitions, perf caps)
src/renderer.js     WebGL1: 2 programs (bg, item), 1 unit quad VBO, texture cache (WeakMap by source), letterbox view, context-loss restore
src/shaders.js      GLSL. lightAt() = flashlight mask, evaluated per fragment in every draw (no fullscreen pass)
src/game.js         state: room, inventory (keys/unlocked/searched), light, per-item hover/glow, transitions ('in'|'idle'|'out'|'end'), door/painting/back taps, hudState(), frame() -> draw list
src/hud.js          HUD 2D canvas at the PS1 framebuffer size: built-in 5x7 pixel font, typewriter message box, key icons + door thumbnails, back chevron. `version` bumps on change
src/input.js        Pointer Events -> move/down/tap/leave in scene coords. Touch moves the light only while the finger is down
src/world.js        generateWorld(seed, db, {ambience, maze}): pure, seeded lock-and-key maze (format documented at the top). Reusable by a future editor
src/rng.js          mulberry32
src/assets.js       loadDB (data/*.json), loadImage, makeSprite (POT pad + alpha hit mask)
src/debug.js        overlay (` key or ?debug): seed, room contents (targets/locks/keys), key locations, fps, slot markers; N = new world, K = all keys, B = start room, A = ambience one-shot
data/items.json     { id: { src, scale, depth, placement:[tags] } }   tags: "door" | "wall" (paintings)
data/rooms.json     { id: { src, slots:[{ id, x, y, scale?, accepts:[tags] }] } }   (x, y = item center, scene px)
tools/serve.mjs     static dev server (--lan, --port=, --dir=). Without --dir, fs.watch re-runs audio.mjs/images.mjs on source changes (debounced)
tools/images.mjs    art-src/** -> assets/**/*.webp via ffmpeg libwebp (incremental, orphan cleanup, never touches assets/audio/)
tools/build.mjs     validate paths -> dist/web -> dist/casa-fantasma-web.zip (hand-written zip writer, deflate)
```

## Rendering model
- PS1 mode (`CONFIG.ps1.enabled`): everything below renders into a low-res FBO (`ps1.width` x 16:9, NEAREST), then `FS_POST` draws it to the letterbox with nearest upscale + `colorBits` quantize using a 4x4 Bayer dither in low-res pixel space. Rects and the beam are snapped to low-res pixels (`ps1.snap`). The scene shaders' noise dither is off in this mode (`uNoise`).
- One draw for the background (blending off), then one draw per item (premultiplied, `ONE, ONE_MINUS_SRC_ALPHA`), then the HUD canvas (`FS_HUD`, texture re-uploaded only when `hud.version` changes).
- Item shader, all in one pass:
  - sprite × light;
  - drop shadow = alpha sampled at `uv - offset` with mip bias (blur), drawn only outside the sprite;
  - outer glow = alpha at a high mip bias, outside the sprite, added on top.
- Shadow offset = `(itemCenter - (beam + handOffset)) * depth * perDepth`, clamped to `maxOffset`. It is computed per frame in `game.frame()`.
- Hit test uses the per-pixel alpha mask in native sprite px. Touch also samples 8 points at `touchSlop`.
- The loop runs only while `game.update()` returns busy (light easing, transition, glow) or while debug is on. Input and resize call `wake()`.
- The letterbox is "contain" at 16:9. Portrait on touch devices shows a rotate hint.

## World generation (maze)
- Seed comes from `?seed=N`, or is random. The game logs `[casa] seed`.
- Rooms form a tree (rooms[0] = start, 3 doors). Door rooms have 2-3 doors; painting rooms 1-4 paintings. "Back" = parent.
- Stages: grow a region behind unlocked doors -> hide key s in a painting room of that region -> lock a free door reachable so far with key s -> it leads to stage s+1 (or EXIT for the last lock). Leftover doors -> decoy painting rooms. Always solvable.
- Each lock gets door art reserved for it (unique in the level), so the key's HUD thumbnail names its door. No art repeats within a room.
- Using a key consumes it. Taking the exit shows "You escaped", then the world regenerates with `seed+1`.
- Seed 42: room 0 doors -> rooms 1, 2, 3; key 0 is behind painting03 in room 1 and opens door11 in room 3.
- Headless check: import world.js + game.js in Node with stub sprites (full masks), tap item centres, step update(0.05). Game has no DOM deps.
- In an occluded/automated Chrome tab rAF runs ~2 fps and dt is capped at 0.05, so transitions take ~10x longer there.
